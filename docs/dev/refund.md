# 退款与报销

退款是挂在原支出上的独立条目，与报销共用同一套机制。模型见 `lib/app/models/ledger_entry.dart`，计算见 `ledger_math.dart`，原支出的退款界面见 `refund_editor.dart`。

## 数据模型

- `EntryType.refund`；`refundOf` 指向原支出 `id`（必填），`settledAt` 为到账日期（`null` = 待到账）。
- 三层金额：`amount`/`currencyCode` 保存退款原币，`accountAmount` 保存实际入账账户金额，`baseAmount` 保存冻结的本位币冲减金额。
- 到账账户 `accountId` 可与原支付账户不同；`occurredAt` 为发起日期；`note` 为备注。
- 原支出缓存 `refundedBaseAmount = Σ已到账退款.baseAmount`，是派生缓存。

## 金额口径

- 只有已到账退款（`settledAt != null`）影响账户余额与原支出净额。旧数据或导入中的待到账退款不进余额、净额或收支统计。
- 统计使用 `netBaseAmount = max(baseAmount - refundedBaseAmount, 0)`；账户余额使用退款自己的 `accountAmount`。
- 退款不计收入，冲减原支出所在月份与分类；余额/资产趋势按退款 `settledAt` 生效，收支统计按原支出 `occurredAt`。
- 禁止超额：Σ退款不得超过原金额，超出时提示并截到「剩余可退」。
- 默认剩余可退金额与退款草稿金额必须按原币 minor unit 归一化；`expense.amount − Σ退款.amount` 的浮点结果不得直接作为金额。唯一口径见 [交易聚合保存与退款金额精度](entry-save-validation.md)。

## 生命周期

- 退款只能从「原支出 → 添加退款」创建；普通记账页的类型选择器排除 `refund`。
- 删除原支出级联删除其退款；删除单笔退款后原支出净额恢复。
- 编辑原支出金额低于已退合计时净额下限为 0，并在界面提示。

## 界面

- 收到退款后，在原支出详情的「退款」区登记金额、到账账户、到账日期和备注。支持多笔退款。
- 保留旧版或导入的待到账记录，可在原支出中选择实际到账日期后保存，或删除该记录。只打开编辑页不会改变状态或金额。
- 退款随父交易草稿、附件一起经 `saveEntryAggregate` 原子保存。退款明细在原支出中管理（见 [known-limitations.md](known-limitations.md) L2）。
- 当前不提供批量报销/批量退款；待报销交易逐笔在交易详情处理。
- 编辑已有退款时，只修改发起/到账日期、备注或状态不得重算已保存的 `accountAmount` /
  `baseAmount`；这两者是历史实际到账与冻结冲抵事实。新建退款的预计金额仍可按当前日期汇率初始化。

## 生成与迁移

- 有原支出编号的账单导入在 plan 阶段按原币、到账账户币种和本位币分别生成关联退款。
- 例外：随手记的「退款」工作表没有原支出编号，导入时按收入兜底（账户余额正确，原支出净额不冲减、收入统计会多出退款金额），不生成关联退款；见 [known-limitations.md](known-limitations.md) L14。
- 本应用 CSV 将每笔退款导出为独立行，通过 `记录编号` / `原支出编号` 关联，保留待到账状态、发起/到账日期、到账账户与三层金额；旧版只有原支出「退款」汇总列的文件仍可导入。
- 旧标量退款数据按原支出三层金额比例合成为关联退款。
- 退款随交易进入备份 JSON；`refundOf`、`settledAt` 参与序列化。

## 验收

- 单笔/多笔部分退款、全额退款的净额与余额；跨账户退款原账户扣全额、到账账户加退款。
- 已有部分退款时，新增默认剩余金额（非整数）保存成功，金额与币种精度一致。
- 待到账退款不进余额/净额/统计，标记已到账后才生效。
- 超额拦截、级联删除、删除退款后净额恢复。
- 备份 round-trip（含待到账退款）一致。
- 退款原币上限与本位币净额分别计算；外币退款遵循 [multi-currency.md](multi-currency.md)。
