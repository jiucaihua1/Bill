# 截图识账与外部意图接口

截图识账和外部意图由用户主动触发，识别后进入记账页。Android 自动识别原型的运行条件见下方。

## 路线 A · 截图识别

- 入口：系统分享 `image/*`；App 内 AI 记账弹层的「截图识账」（相册选图）。
- 管线：本地 OCR（`google_mlkit_text_recognition`，中文模型，端上离线）→ 文本 → AI 解析（复用 AI 记账管线，`requestCapturedEntryDraft`，含无数字短路与文本截断）→ 草稿 → `EntryDetailPage` 确认。
- 分享进来的图片不落库不留存；用户勾选「保存为附件」才随交易存 `attachments` 表。
- App 内相册选图、拍照附件与头像读取完成后立即删除 `image_picker` 在应用缓存里的副本；
  用户相册原文件不变。OCR 或解析失败同样在 `finally` 中清理。
- 其他 App 分享的 `content://` 图片由原生层分块读取并累计大小，超过 25 MB 立即停止，不做全量 `readBytes()` 后再检查。
- 条件导入两件套 `screenshot_recognizer_io.dart`（ML Kit）+ stub（测试宿主 `recognitionSupported=false`）。

## 路线 B · 外部意图接口

- 显式导出的 Intent：Action `top.talyra42.verifin.action.CAPTURE_TEXT`，Extra `text`，目标 `ShareReceiverActivity`；Tasker、MacroDroid 等自动化工具用它送入账单原文，解析交给用户配置的 AI。用户文档见 [automation.md](../product/automation.md)。
- 安全边界：文本输入长度限制、简单频率限制；收到后只产草稿弹确认，绝不静默落账。
- 应用锁启用时，分享/采集与小组件路由入口先等待锁屏解除，再消费原生队列中的内容；
  锁屏期间不发起 OCR、AI 请求或切换账本。

## 截图与外部意图的共同约定

- **AI 为硬门槛**：两条路线都依赖 `AiSettings`，未配置时入口引导去 AI 设置页；主推本地 Ollama/LM Studio（文本不出设备）。
- 图像默认走「本地 OCR → 文本 → 现有 AI 文本管线」，不直接把图片发给模型。
- 采集支出的付款账户按「支付方式」或「付款方式」匹配。「零钱」对应微信支付，「余额宝」对应支付宝。账户未匹配时，草稿显示「无账户」，由用户确认或选择。
- **无新增数据表**：草稿当场确认或放弃，不落库；新增偏好仅为设备本地 KV，不进备份。
- 截图原图留在本机。只把 OCR 文本发往用户配置的 AI 端点。

## Android 自动识别原型

微信商户付款成功页的识别条件和排查说明见 [微信商户付款自动识别](wechat-auto-capture.md)。

- 用户启用自动记账并在系统授予相应权限后，本地解析所选应用的支付通知或可访问的付款、转账页面。权限页区分系统授权与实际服务连接。
- Android 14 及以上可在已授权的微信商户码和个人收款码付款结果页进行本地窗口 OCR。截图只在内存处理，切换窗口、锁屏或系统拒绝截图时停止。
- Android 14 及以上，开启通知读取和无障碍后，新到达的微信或支付宝付款通知可触发相应前台窗口的本地 OCR。页面必须确认付款成功和唯一金额。通知明确给出金额时，必须与页面一致。窗口已关闭或识别不一致时，这条辅助链路不会生成草稿。旧版 Android 仍使用原来的通知文本识别。
- 建设银行来源可单独开启，读取建行手机银行的消费、支出或扣款通知。通知明确指向支付宝或微信时，只核对该钱包的当前支付页，与钱包通知共用同一核对流程。无钱包标记的建行通知仅核对当前建行 App 的付款成功页。短信不参与识别。
- 微信转给他人的款项建议记为支出，收到他人的款项建议记为收入。方向或金额无法唯一判定时跳过，待收款的草稿注明状态。
- 同一个付款页反复刷新时只提醒一次。开启悬浮窗权限后，Android 在当前应用上方显示与应用内相同的确认面板，沿用分类图标网格、账户、标签、备注和预算相关选项。键盘打开时，备注、账单选项和底部按钮保持可见，上方分类区域可滚动。取消会丢弃草稿。
- 悬浮窗受系统限制或启用了应用锁时，可从通知打开小禾确认。非人民币本位币账本在完整记账页确认汇率。悬浮窗中的 Flutter 引擎只显示界面，落账统一交给小禾的账本控制器。临时草稿编号只能消费一次，有效期为 15 分钟。
- 支付平台和购物平台在 2 分钟内报告同一明确购物平台和同一金额时，归并可唯一配对的草稿。两侧都有商户订单号时需一致。首条草稿保留，后到的匹配记录只过滤一次。缺少商户线索或有多个候选时分别交给用户确认。
- 付款草稿按商户和商品关键词建议当前账本分类，使用分类语义键。京东、拼多多缺少细分类线索时建议「购物」。其余未知分类沿用账本已有的「未分类」，或由用户选择。
- 拼多多优先读取明确的实付金额，只有下单成功或预计金额时不生成草稿。微信转出支持聊天卡片，也支持含「支付成功」「待…确认收款」「完成」和唯一金额的转出结果页。预览使用同一个面板和一笔示例转账。
- 控制中心「截图记账」磁贴打开选图入口。Shizuku 只展示授权状态，识别使用系统授权的通知或无障碍通道。

## 原发布方案未采用的通道

| 通道 | 原因 |
|------|------|
| NLS 通知监听 | 与「数据自主、本地优先」的产品立场冲突，且 App 被杀即停、依赖前台服务保活 |
| 无障碍读屏/截屏 | 同上，且是最重的权限 |
| 短信监听 | 同上（`RECEIVE_SMS` 敏感） |
| Xposed/Root/LSPatch/Shizuku | 用户群与 GitHub Releases 分发模式不符 |
| MediaProjection 常驻录屏 | 监听类，且 Android 14+ 授权更严 |

## 实现落点

- `lib/app/screenshot_recognizer_*.dart`：OCR 两件套；
- `lib/app/ai/ai_entry_parser.dart`：`buildCapturedEntryPrompt` / `requestCapturedEntryDraft`；
- `lib/pages/capture_entry.dart`：识别流程；
- 原生 `ShareReceiverActivity` + MainActivity 采集桥接；`consumeCaptureImage` / `consumeCaptureText` 拉取（仿快速记账 intent 模式，保持单实例）。

## 验收

- 微信/支付宝/银行 App/云闪付真实账单截图各若干张，金额与收支方向必须准（分类允许用户改）；分享入口冷启动、已运行、连续分享多张均可用；识别失败有兜底草稿。
- 自动化 Intent 冷启动（App 未运行）与运行中都能正确弹出确认页。
- 纯风景图（无文字）提示「没识别到文字」；聊天/网页图（有文字非交易）提示「未识别到交易」；无数字文本不白调 AI；AI 报错/超时弹本地化错误提示——全部不崩、不落账。
- OCR 依赖 ML Kit，release 的 R8 行为与 debug 不同，须用个人版签名 release APK 真机验收。
