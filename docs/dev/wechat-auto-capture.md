# 微信商户付款自动识别

本文记录微信付款和好友转出结果页的当前识别链路，供维护和排查使用。通用的权限、草稿与悬浮窗说明见[自动采集](auto-capture.md)。

## 使用条件

- 用户已开启自动记账、微信识别，并在系统设置中启用小禾的无障碍服务。悬浮确认还需要悬浮窗权限；不可显示时使用通知兜底。
- 微信商户付款的窗口截图接口仅在 Android 14 及以上使用。系统拒绝截图、锁屏或离开目标窗口时不会继续识别。
- 此次手机验证中，用户反馈微信付款成功页已经能触发记账弹窗；尚未确认该次触发是控件文本直接解析还是截图 OCR，也未分别验证每项配置的作用。

## 无障碍服务配置

小禾使用自己的 `AutoBookkeepingAccessibilityService`，并不调用或冒充 TalkBack 服务。配置见 [`auto_bookkeeping_accessibility.xml`](../../android/app/src/main/res/xml/auto_bookkeeping_accessibility.xml)：

- 接收窗口状态变化、窗口内容变化和无障碍焦点事件；声明 `feedbackSpoken`。
- Debug 版保留连续的快速窗口状态事件，使短暂的付款码入口也有机会记录。截图仍沿用会话内的等待和重试间隔。
- 启用视图 ID、交互窗口和非重要视图的报告，允许读取窗口内容及截图；事件来源限定为配置中的微信等应用。
- 服务收集当前窗口和事件来源的文本、内容描述，先交由 `AutoBillParser.handleScreenTexts` 尝试解析。读取或事件发送行为仍受 Android 和目标应用限制。

`feedbackSpoken` 只是无障碍反馈类型的声明，不会使小禾变成 TalkBack，也不能保证取得 TalkBack 所见的全部控件。是否必须开启 TalkBack 才能出现特定焦点事件尚未单独验证。

## 微信截图 OCR 的触发与校验

实现见 [`WechatMerchantPaymentCapture.kt`](../../android/app/src/main/kotlin/top/talyra42/verifin/WechatMerchantPaymentCapture.kt)：

1. 微信 App 支付入口、商户扫码付款页、个人收款码付款页或好友转账页发生窗口状态变化后，建立一次有效期为 90 秒的付款会话。
2. App 支付会话匹配微信轻应用付款结果页。好友转账、商户扫码和个人收款码将确认页、输密码页与结果页共用的窗口视为候选。候选窗口可以切换，同一窗口的内容变化或成功控件也可触发补读。候选切换后，旧窗口的截图或 OCR 回调失效。
3. 页面文本已经识别为账单时不再截图；否则等待 650 毫秒，再检查会话、设置、锁屏状态、当前窗口和包名，然后请求系统窗口截图。截图成功后再次核对当前窗口。
4. 图片仅在内存中交给本地 ML Kit 中文 OCR。App 支付结果需识别「支付成功」和「返回商家」，商户扫码结果需识别「支付成功」。金额在页面上方中央的实付区域取值，排除下方优惠券金额。个人收款码因头像使金额更靠下，使用较低的实付区域。整图未读到唯一金额时，对实付区域缩放后补读。
5. 草稿经现有去重与确认流程处理，不会静默落账。

好友转出结果页的无障碍文字要求「支付成功」「待…确认收款」「完成」及明确金额。OCR 在该转账窗口内校验「支付成功」和待收款提示。整图未读到状态时，对窗口上半部的中央结果区域再做一次中文 OCR，并使用该区域的金额。状态齐全但整图未读到唯一金额时，用同一个识别器重读待收款提示下方的金额区域。失败日志区分状态缺失与未读到唯一金额，不输出识别原文。草稿注明待对方收款。

好友转账、商户扫码和个人收款码的候选截图至少间隔一秒。OCR 未匹配时可在当前候选窗口补读一次，后续仍响应页面变化。个人收款码补读可使用可见付款区域，避开系统状态栏，要求同一候选窗口仍全屏、前台且未被覆盖。若个人收款码漏读「支付成功」，同一窗口的「完成」控件或独立 OCR 文本行也可用于判断结果，仍需识别唯一实付金额。App 支付结果页在未匹配时可在同一窗口延迟重试一次。结果窗口 ID、页面类名和文本依赖微信实现。

个人收款码结果确认金额后，可将正上方带遮盖实名后缀的显示昵称填入备注。昵称从同次 OCR 的实付区域或整页文本中提取。

微信商户付款成功页校验通过后，优先读取带标签的商户名。顶部控件或 OCR 文本呈现「支付成功 → 商户名 → 实付金额」时，也可将无标签的商户名填入备注。平台标签仍由已识别的电商订单决定。

Debug 版在自动记账和微信识别开启时可记录付款码窗口事件。已知入口为 `WalletOfflineEntranceUI` 和 `WalletOfflineCoinPurseUI`；若只收到后续的 `UIPageFragmentActivity`，记录为未分类窗口。日志把时间、类名、窗口 ID 和事件类型写入应用私有文件，保留最近 128 条。该诊断链路只记录事件。手机可脱离电脑，重新连接后用 `adb shell run-as top.talyra42.verifin.personalledger cat files/wechat-payment-code-windows.log` 读取。

## 弹窗耗时与排查

手机现有日志中曾观察到草稿创建到悬浮窗首帧约 1.14 秒和 1.41 秒；它们不包含此前页面识别时间，也不能拆分账本准备、渲染引擎初始化和绘制耗时。当前安装的是 debug 构建，不能作为正式版性能结论。

每次悬浮窗都会新建 Flutter 渲染引擎，并在关闭时销毁；窗口先显示，Flutter 内容随后绘制。无障碍节点遍历、草稿同步写入和截图位图复制也可能影响响应。`feedbackSpoken`、新增焦点事件和非重要视图配置各自的影响尚未通过对照测量，不能归因于其中某一项。排查时可记录不含账单内容的阶段时间，比较识别、草稿创建、账本准备、引擎启动和首帧时间。
